# 多视图比对与验收

## 对照顺序

先外廓和净空间，再分件关系，最后视觉细节。逐项检查：

| 方向/状态 | 重点 |
|---|---|
| 正面 | 总高宽、屏幕位置、门宽、Logo/手扣/格栅占比 |
| 左右侧 | 深度、斜面/折点、前凸量、机柜位置、屏幕倾角 |
| 后面 | 柜门分件、留白、立柱、散热口 |
| 顶部 | 内外轮廓、壁厚、空腔、门闭合与屏幕占位 |
| 底部 | 底板封闭、脚轮/支撑、地台相对位置 |
| 开门和内部 | 铰链、门上部件跟随、密封、地台、内衬和出风口 |
| 其他配置 | 布局变化、配色、玻璃印刷、灯色；不是仅切换文件名 |

没有对应资料的方向不计为“已经匹配”，但仍须检查模型本身是否存在穿插和缺面。

## 公平配准

参考、模型渲染及叠线并排保留。相同视图采用统一比例、显式基准点；平移用于对齐地面/中心，不用于逐件拖动掩盖误差。不要非均匀拉伸、液化、光流变形或每个部件分别缩放对照图。修改应发生在模型或经证据校准的相机里。

比例由尺寸和相机参数确定。例如正交相机画面高 2 m，渲染高 1000 px，对应 500 px/m；参考已知高 1.8 m 占 900 px 时比例相同。不能在每轮都根据错误模型当前包围盒重新归一化，从而消除本应被发现的尺寸偏差。

轮廓遮罩与关键特征线分开：外轮廓重合也可能门、UI、内部布局错误。色彩边缘可能来自高光、纹理、阴影，不应直接当成实体边界。源图只有 1–2 px 的不确定性时，记录不确定范围，不为追逐噪点盲目改尺寸。

## 随包轮廓工具

输入必须是黑底、白色产品区域的灰度 PNG 遮罩；先从合适视图可靠生成，不能简单把明亮的产品当背景抠掉。安装 Pillow 后，从本 Skill 目录运行：

```sh
python3 scripts/compare_masks.py --reference ref_mask.png --model model_mask.png --scale 1 --reference-anchor 300 900 --model-anchor 300 900 --basis "同投影、500 px/m，锚点为地面中心" --output qa/front
```

比例将模型像素映射到参考像素；锚点分别使用各自图像中的 `(x, y)` 像素坐标。

输出 `overlay.png`（红=仅参考、蓝=仅模型、紫=重合）、`model-aligned.png` 和 `report.json`。IoU 只衡量这张投影的区域重合，不证明内部结构、所有视角、制造尺寸或模型质量。

## 迭代与退出

每轮写下最显著的差异、修改对象及验证视图。用可重建脚本或明确部件编辑，保留可回退版本。改门宽需复核正/顶/开门；改壁厚需复核净空间和闭合；换材质需复核正面与斜视。

没有明显误差改善，先检查参考对应关系、尺度、相机、法线和遮挡，而不是继续堆细节。每轮没有新证据、差异已落入资料精度范围时，记录限制并交付已核对结果，不无限尝试。

若用户给出截止时间，在该时间前冻结可审核版本，将已确定部分与未完成/未证实项分别列出；不能为了赶时间把评审版称为精确工程交付。

## 最后核对

实测单位与总体尺寸；检查有限坐标、意外重复面、穿插、法线、UV 和需要闭合的实体。检查修改后的材质索引、导出贴图与动画。玻璃等合理薄片不应被“一律必须实体”的检查误报。

逐张看正式渲染，放大关键区域；再在真实浏览器检查相同版本。输出清单记录模型、贴图、渲染和查看器的版本/哈希，刷新后对上当前文件。交付说明分别写清“几何检查通过”“交互通过”和“视觉尚存差异”，不能相互替代。
