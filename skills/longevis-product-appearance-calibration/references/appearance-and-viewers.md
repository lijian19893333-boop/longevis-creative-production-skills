# 外观判断与显示链路

[English](appearance-and-viewers.en.md)

## 材质判断

- **涂层与裸金属：** 黑色涂层仍需要可辨的宽高光。先判断基材是否被不透明涂层覆盖，再确定 metallic；工业产品并非所有表面都 metallic=1。
- **玻璃：** 同时观察反射和透射。glTF alpha 混合与 `KHR_materials_transmission` 不同。检查 renderer 的实际支持和加载后的值；原有开门代码若随角度降低 alpha，可能破坏已经校准的透射效果。
- **木材：** 细木纹靠真实尺度、方向、粗糙度与低幅法线，大面积底色保持可信。不同木种与外饰不能仅用同一张通用木纹换色。AO 不应把所有缝隙压成黑线，也不能烘入可切换光源的颜色。
- **织物与橡胶：** 织物依靠微观起伏、粗糙度与有限 sheen 建立层次；保留缝线、压槽、膜面与实际 UV。橡胶通常比相邻裸金属更散射，但以参考和实际材质为准。
- **UI 与标识：** 以原始贴图为依据，避免被整体调色或微纹理覆盖；检查息屏与恢复状态。

## 局部有色光的判断方法

在带有色光的内饰中，把框架材质、玻璃透射、木纹与分布式光源分别调节。先消除不合理热点，再判断是否需要低位反弹近似；近似光并非物理测量结果。

检查灯珠颜色是否可读、木纹在受光区是否保留、明暗是否随距离变化、黑位是否有层次、玻璃是否兼有内饰可见性和边缘反射、接触阴影是否与主体相接。这里给出判断标准，没有可直接移植到其他产品的准确色值或光强。

## 资产和查看器集成

静态目录可能经过运行时派生后改为加载另一个模型。专属页面还可能分别加载 closed/open/interior/floorplan 文件，下载按钮可能指向另外的别名。沿实际网络请求追踪每个 URL，不能只搜索源文件名。本公开包不解析任意 JavaScript、数据库或产品目录。

通用控制器、设备控制器与专属查看器可能在 load 后改写颜色、发光和透明度。模型正确但画面不对时，检查最终材质值。增加 `KHR_lights_punctual` 后，关闭发光材质并不会关闭实际灯光。脚本写入的 node extras `controlMaterial` 和 `appearanceLightGroup` 只是元数据，查看器需要自己读取并接入开关。

核对环境图、色调映射、曝光、阴影、单位和缓存指纹。原生模型与网页加载的文件未必相同，网页截图也不能证明原生渲染通过。记录渲染器及版本和验证过的功能，而不是假定所有查看器支持相同扩展。

## 原生工具与异步操作

Blender 的节点输入名、合成器 API 和 GPU 选择随版本变化；先检查当前实际接口，避免沿用旧版属性名。CLI 执行 Python 时，使用支持的 `--python-exit-code 1` 让 Python 异常反映在进程退出状态中，并检查日志。退出码本身不证明视觉正确。

异步导出与换模应绑定任务所属模型。旧任务完成时，只恢复该模型的尺寸、机位和忙碌状态；若用户已切换模型或查看器已销毁，丢弃过期恢复操作。特别验证“导出 PNG 后立刻切换配置”的时序。
