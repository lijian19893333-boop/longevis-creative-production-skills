# 配图、融合与可编辑交付

[English version](visual-production.en.md)

## 从行业体验建立视觉方向

明确受众熟悉的动作、场地和穿戴细节。高尔夫等运动项目的触动力来自正确的握杆、挥杆、打位、球道、教学关系与装备尺度，而不是装饰性的球、旗和蓝色电路。

科技感可通过精密结构、材料、光线、测量信息和产品界面表达。时尚感可通过服饰比例、材质、搭配和摄影体现。两者应围绕同一真实产品。

## 两种可选择的视觉组织

| 方向 | 适用内容 | 执行方式 |
| --- | --- | --- |
| 干净编辑版 | 信息密度较高、品牌强调简洁 | 有节奏的留白、明确的字体层级、少量独立主视觉与原生图表 |
| 场景融合版 | 体验、品牌、产品与渠道需要现场感 | 全幅或大幅真实场景，预留文字区域，产品与环境自然过渡 |

同一主稿可混用两种组织方式，遵循一个品牌体系。不要为了证明有背景而让每页同样拥挤，也不要把所有业务页都退化为相同纯色底。

既有明确偏好时直接沿用；提出多个方案用于选方向，不把方案对比页自动堆入路演 BP。

## 图片资产计划

图片先分配，再生成。每张内容图一个用途、一个主稿页码。内容图片和背景统一参与去重；品牌 Logo、页眉和通用小图标单独登记。

可用的画面尺度包括：大场景俯瞰、人物全身、动作近景、器材细节、材质微距、结构爆炸、界面体验、包装与交付细节。

同一教练换裁切，同一腰带换调色，同一草坪加不同渐变，都不构成独立画面。生成新视角也要检查是否只是同一构图的小变体。

生成图提示词应包括：

1. 用于哪一页与要支持的主题。
2. 主体、动作、场景与镜头尺度。
3. 主体位置和文字所需的留白。
4. 材质、光线与该项目的调色基准。
5. 产品/人物动作必须保持的细节。
6. 不生成页面标题、伪数据、第三方标识或带 UI 的整页 PPT。

保存确切提示词、输入参考、生成模式、输出文件和页码。所有项目资产复制到项目目录；不要只依赖工具的默认生成目录。

## 产品设计一致性

选定一个设计基准，记录轮廓、尺寸约束、CMF、机械关系、隐藏电子仓、佩戴方式与品牌位置。主视觉、佩戴图、爆炸图、官网图和 App 中出现的设备都按该基准。

工程参数与设计提案分开。外观图不能证明防水、精度、电池续航、量产或认证。结构爆炸图如果只是表达概念，不画成已完成的工程验证结果。

## 自然融合

使用透明资产或为版面构图专门生成主视觉。光向、透视、色温、接地阴影和清晰度一致，产品边缘自然。

不截取整张参考页贴到新背景，也不保留产品图的矩形白底。单纯把白边模糊掉，主体仍显得漂浮时，需要重做光影或构图。

文字区域优先保持平静。密集的建筑灯、金属反光、沙坑、夕阳水面、包装纸和草坪高光容易破坏正文对比。可以用原生遮罩调整曝光，但不能把图片压到几乎看不见。

## App / 官网

界面与产品承诺一致。用真实用户动作组织：连接/校准、记录、比较、复盘等，以项目功能为准。

界面图中的数值若无实测证据，标示示例。不要让画面暗示系统已经支持未确认的自动识别、全身捕捉、疾病诊断或成绩提升。

在 PPT 中保留关键文案、数据图表与说明为原生对象。设备框与复杂产品渲染可以是图片。不要仅为看起来“可交互”堆放无意义卡片和按钮。

## 可编辑与导出

遵循当前 presentations 技能。工具版本和运行时路径由环境发现，避免把一次任务的绝对路径写成长期依赖。

- PPTX 中的文字、表格、图表和必要的结构图保留原生对象；数据图表应带可用的工作簿绑定。
- 仅替换背景时，优先针对图片关系和需要的遮罩做最小修改，保留原生内容。导入/再导出可能改变图表绑定，必须验证实际包结构。
- OOXML 图片目标可能是相对路径，也可能从 `/ppt/...` 开始。解析后再比较媒体哈希，不能只比较文件名。
- PDF 优先保留矢量/文字输出。若当前引擎的 PDF 导出确实不可用，可把最终 PPT 逐页高分辨率渲染成静态 PDF 预览，清楚说明其预览性质，PPTX 继续作为可编辑源。
- PDF 预览必须来自最终 PPT，不能把旧版渲染混入新版本。

## 图片去重辅助脚本的边界

`scripts/audit_pptx.py` 仅使用 Python 标准库，以文件内容 SHA-256 检查被幻灯片实际引用的图片。跨页同字节图片即使媒体名称不同，也会报告。

它也报告图片引用缺失、原生表格/图表数量、图表所在页和嵌入工作簿数量。返回码0表示这些检查未发现问题；返回码2表示图片复用或缺失，需要人工处理。

它无法理解图片主题、动作是否正确、产品是否一致、裁切/调色后的近似复用、图片中文字或版面美感。因此整套总览和原尺寸逐页视觉检查仍是必要步骤。
