# 宝塔与自托管网站发布运行手册

[English equivalent](deployment-runbook.en.md) · [返回 Skill](../SKILL.zh-CN.md)

## 1. 确定目标和变更等级

站点登记表应包含：发布编号；环境与域名；源码版本和工作区状态；构建/启动命令；实际产物；生产/候选/旧版本目录；运行时版本及可执行文件；服务用户；托管者；监听地址/端口；Nginx 配置；数据库、私有媒体、env 和备份位置；切换与恢复步骤；授权范围；验证负责人。登记的是当前可核实事实，未知项明确标注。

| 变更 | 发布范围 |
| --- | --- |
| 已有后台支持的文案、图片、排序 | 快照→草稿→预览→发布→公开页面检查 |
| 源码、组件或多页面内容同步 | 同步内容真源→构建→独立候选→版本切换 |
| API、数据库、env、登录/权限、托管者、Nginx 或域名/DNS | 应用、配置、数据迁移与恢复一起处理 |

混合请求按最高影响面处理。例如“换首页图片并改表单 API”属于完整应用发布。不要因为第一项简单就遗漏后端。关键目标未知时先查配置、项目文档和现有进程；查不到才询问必要信息，不猜生产路径。

## 2. 从项目发现构建与运行契约

读取 README、部署文档、包管理器锁文件、scripts、框架配置、现有 Nginx 与进程参数。确认构建命令、输出目录、静态导出或服务端执行模式、运行依赖、端口/env 来源以及健康检查入口。使用该项目实际的包管理器及锁定版本，不预设某个 `npm`/`pnpm` 脚本存在。

静态输出常见 `dist/index.html`，SSR 常见 `.output/server/index.mjs`，但目录名只作线索。两者同时存在时排查旧构建和多个目标；使用干净候选工作区与明确构建脚本确认结果。其他框架输出按自身契约判断。预期产物缺失或启动模式不一致时，先修复再上传。

静态前端也可能有 API、表单、后台、数据库或邮件服务；逐项确认依赖，不因入口 HTML 存在而判定整站纯静态。

## 3. 构建、打包和校验

在本地或隔离环境执行项目已有且适用的类型检查、测试、lint、构建及业务检查。记录实际命令、结果和源码版本；没有的检查写明，不编造通过记录。

发布包包含运行契约所需产物、必要运行依赖、迁移脚本和脱敏配置模板。排除真实 env、凭据、数据库、私有媒体、备份、Git 历史、开发缓存和无关原始媒体。部分 SSR 运行时依赖包内依赖或框架追踪输出，应按项目验证，不能机械删除 `node_modules`。

以下是仅验证已有压缩包的命令示例，变量需设为本次实际文件；它们不执行部署：

```bash
release_archive='/absolute/path/to/release.tar.gz'
tar -tzf "$release_archive"
gzip -t "$release_archive"
shasum -a 256 "$release_archive"  # Linux 可用 sha256sum
```

检查清单中的路径和敏感文件，记录包大小与 SHA-256。服务器收到后再次核对摘要，再解压到本次独立候选目录。完整性校验只证明传输一致，不证明包可运行或没有敏感数据。

## 4. 备份与持久化数据

发布前保留旧版本，备份数据库、私有媒体、内容快照、env、Nginx 和实际服务配置；备份放在受限且非公开的位置。数据库备份需按引擎使用一致性方法：SQLite 注意活动写入/WAL，其他引擎使用其支持的快照/导出机制。验证备份可读，并在隔离环境检验恢复步骤，不能把“文件存在”当作恢复成功。

把可变数据、私有媒体和日志移出可替换版本目录；敏感数据及备份也必须在 Web 根目录之外。限制到服务用户所需权限，不用 `chmod -R 777`。如果现有数据位于旧发布目录，先准备独立持久化位置并核对数据一致性，再安排切换。

## 5. 环境、迁移与托管

真实 env 只保存在服务器受限文件或安全配置入口；日志展示时脱敏。候选环境不得误连生产写入目标或发送真实客户消息；按授权使用测试数据或受控测试。

新库初始化与既有库升级分开处理。先检查迁移账本、目标、备份和兼容性，再运行本项目提供的迁移机制；不重复手工执行未知 SQL。记录迁移后的读写检查和恢复条件。破坏性迁移需明确应用版本回退是否仍能读取新结构。

每个服务只选一个实际托管者：宝塔 Node、systemd 或 PM2。登记项目不应另起重复进程。按配置核对实际监听和服务用户；通过本机反代时通常绑定回环地址，容器/网络拓扑不同则按已验证网络设计配置。

托管者切换是一项独立服务变更：先核对 env、工作目录、运行时、持久化数据与健康检查，准备新旧进程和流量切换顺序及回滚；不先停唯一旧服务再现场补配置。

Nginx 的静态站 fallback 只对相应前端路由启用；API/管理/私有媒体路径应有独立匹配规则，避免把失败 API 返回成 `200` HTML。SSR 根据项目反代到服务。配置修改先 `nginx -t`，通过后才 reload。systemd 配置变化按需 daemon-reload，再重载/重启对应服务，检查状态和日志；PM2/宝塔按实际托管工具操作。

## 6. 候选验收与切换

先用独立目录、测试域名或受控 Host 验收候选版本，避免覆盖唯一生产目录。验证项目实际要求的项目：

- 首页、核心页面、深链、404、静态资源及预期版本；HTTP 状态与内容共同正确。
- 后端健康、数据库迁移、日志和服务重启后的运行状态。
- 表单/API 的字段、成功/失败、重复提交、状态码、数据落库/邮件及权限/限流边界；用授权安全测试数据，前后端为同一版本。
- 后台登录、媒体草稿/预览/发布/下线、公开门禁和未授权访问行为。
- 视频实际播放与所需 Range 请求；大资源、错误域名、临时链接和第三方依赖。
- HTTPS、canonical、robots、sitemap 和后台 noindex；桌面及约 390px 手机布局，必要时目标内置浏览器。

候选通过且生产切换已获授权时继续切换，无需重复询问相同授权。超出范围的 DNS、域名、数据删除等动作单独澄清；继续可独立完成的准备。使用项目已验证的版本指针、配置或流量切换方法；切换链接是否原子取决于文件系统和实现，不能只写“原子发布”而无验证。

## 7. 正式公开验证与证据边界

切换后重新验证正式域名的 TLS、目标版本、关键路由、API/表单、媒体与日志。内网健康和测试域名通过不足以证明公开入口正确；缓存/CDN、DNS、多源站都可能仍指向旧版本。

域名切换时核对权威 DNS、目标地址、证书主机名/证书实际内容、HTTP 响应与页面版本。若有 CDN/反代，分别解释边缘与源站检查。传播未完成或无法从外部验证时记录限制，不声称所有访问者已切换。

把结果分别记录为本地构建通过、候选通过、切换已执行、公开入口已核验、业务闭环已核验。缺一项就保留该项待验，不升级证据。

## 8. 回滚

页面白屏、服务无法启动、API/数据库失败、混合静态资源、权限泄露或 TLS/Nginx 异常时，停止继续叠加变更，保留日志和当前版本。按预案将流量/服务指回上一版本，并按需重启对应服务。数据库恢复按已验证的引擎和项目方案执行；单独回退代码无法保证撤销数据迁移，也不能随意删表。

恢复后重新验证正式页面、API/后台、媒体、权限和日志。记录原因、恢复版本、时间、数据影响与后续修复。保留备份按项目保留策略清理，不能在验收前删除唯一恢复副本。

## 9. 发布记录模板

```text
release_id / 时间与时区：
站点 / 环境 / 域名 / 授权范围：
变更等级 / 摘要 / 影响：
源码版本 / 工作区状态：
实际构建命令 / 检查结果：
产物 / 包大小 / 清单 / SHA-256：
旧版本 / 候选 / 当前版本：
备份位置与恢复验证（不写凭据或私有内容）：
迁移 / 托管者 / 端口 / 配置动作：
候选检查 / 正式 URL 与业务流程结果：
未验证项 / 已知问题：
回滚步骤 / 数据兼容性 / 回滚结果（如执行）：
```

本手册为公开通用流程，不包含生产站点历史、账号、凭据或实际部署结果。实际命令和长期事实由各项目自己的部署文档与发布记录维护。
