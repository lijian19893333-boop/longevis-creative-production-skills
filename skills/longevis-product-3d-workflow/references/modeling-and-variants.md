# 建模与方案迭代

[English version](modeling-and-variants.en.md)

在源码入口集中定义尺寸和部件配置；界面标签、导出说明和校验从同一参数来源读取。

可采用的坐标约定：X 左右、Y 前后、Z 向上，前面为 −Y，右墙为 +X。这是项目约定，不是唯一坐标规则。导出 glTF 通常转换为 Y 向上，查看器的门轴与机位需随转换验证。

| 表达 | 落实方式 |
|---|---|
| 正面宽度 | 标明宽度对应哪一面，不依赖默认长宽顺序 |
| 门框改宽 | 分别计算框外廓、门板、净开口，不让一个值错误覆盖三者 |
| 把手在门右侧、远离边框 | 记录中心位置、边缘净距、握持空间；检查内外两侧 |
| 合页在内、门内开 | 固定件与活动件分组；绕实际轴旋转并检查扫掠空间 |
| 沙发背靠右侧内壁 | 将靠背方向及家具包络变换到世界坐标，检查开门与通道 |
| 屏幕多少英寸、16:9 | 英寸是对角线；分别记录有效显示区与整机边框 |
| 内饰三块、上中下拼色 | 用三块通长板和两条表面细缝表达，不用大量小块或实际漏缝 |

16:9 有效显示区：`d_m = diagonal_inch × 0.0254`，`w = d_m × 16/√337`，`h = d_m × 9/√337`。如屏幕竖放，说明旋转关系，不把 9:16 误记为横屏。

## 对象、材料与运动

建议部件集合：`Body`、`Frame`、`Door`、`Window`、`Lining`、`Furniture`、`Devices`、`Ceiling`、`Studio`。名称不必照抄，但应能稳定选择组件，避免依赖对象序号。

门板、两侧把手、活动合页挂在共同门轴下；固定合页属于舱体。检查闭门、半开、全开，并检查运动过程中是否碰家具、地面或边框。

材料厚度用几何表达；漆面、皮革、木纹、金属与透射用材质表达。贴图需要打包或列为外部依赖。网页模型的透明参数与离线光线追踪可能不同；为出图修正透射时记录调整，保留源文件。

若涉及承压壳体、结构型材或门锁，记录用户指定值与示意假设。外观模型不能代替强度计算、连接设计、制造图或试验结论。用户需要这些成果时单独定义工程任务。

## 版本与同步

按项目需要使用独立目录或版本控制，例如：

```
project/
  brief.json
  variants/A/v2/{build_model.py, model.blend, model.glb, checks.json}
  variants/B/v4/{build_model.py, model.blend, model.glb, checks.json}
  renders/brochure-01/
```

每版记录 `parent_version`、修改范围、源文件哈希、确认值和未决项。用户要求派生时保留父版本；明确要求同步后可以更新指定方案，但仍保存可回溯状态。

同步前列出共享模块与方案差异。例如 A 圆窗、B 圆角方窗，两者共享吊顶、家具、地板和后墙控制屏。更新共享内饰时，前墙饰板仍须适配各自开孔；不能整块复制导致窗洞不匹配。

保留检查比较实际几何、世界变换、拓扑、材质分配及贴图；极小浮点差异可给出合理容差。文件哈希用于证明整个文件没被写改，不能证明两个不同文件里的部件等价。

## 查看器与交付模型

导出 GLB 用于交互审阅；原生文件和建模源码用于后续修改。是否需要 OBJ、STEP 或其他格式由用途决定，不把网格格式伪装成可制造参数化 CAD。

检查纹理路径、模型尺度、观察方向、相机裁切和门运动。查看器把剖切、正常外观和内饰模式说清楚；不要将仅用于观察的隐藏状态保存成产品缺件。
