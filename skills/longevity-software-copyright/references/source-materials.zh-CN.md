# 程序材料与本地工具

## 先确定申请的软件边界

选页前先确定登记的程序。记录源码版本、软件名称／版本、入口、模块、语言、开发者／权属依据及单独维护的控制器固件。查看构建配置和页面路由。有安装包时核对源码、安装包和截图版本，不静默改版本。APK 构建成功不能证明已安装、已硬件通信或通过整机验收。

审查并记录纳入顺序。相关自有程序、必要的自有界面资源或嵌入逻辑应纳入；排除第三方、生成、测试或演示文件需说明理由。字母排序可以复现，不证明程序结构正确。第三方源码不自动成为自有源码，不能为了页数排除不方便的自有模块。

McgsPro 等图形化 HMI 应保留原生工程和哈希，尽可能通过平台导出画面、对象配置、事件、脚本及相关逻辑。二进制字符串恢复在覆盖范围未证明前属于局部提取。记录方法、偏移／记录编号，分清配置与脚本。文本片段不能证明全部原生逻辑已恢复。工具对 `.MCP` 刻意只做清单与哈希登记。

## 使用工具

需要 Python 3.10+，只使用标准库。命令相对本 Skill 所在目录执行。对源码副本或冻结版本操作。建立 `files.txt`，每行一个人工核对过的相对源码路径，排列顺序即输出顺序。不支持通配符，也不自动吞入整个目录。以下为合成名称：

```text
app/src/main/java/example/MainActivity.kt
app/src/main/java/example/SessionState.kt
```

```sh
python3 scripts/source_materials.py inventory ./project-copy --files ./files.txt --out ./work/source-manifest.json
python3 scripts/source_materials.py extract ./project-copy --manifest ./work/source-manifest.json --out-dir ./work/material-v1 --name "示例控制软件" --version "V1.0"
```

输出放在源码目录外。已有清单和输出目录不覆盖。UTF-8 严格解码；确有其他编码时用 `inventory --encoding gb18030` 等已核对编码，不能用替换解码丢字符。拒绝符号链接、重复路径和越出源码根目录的路径，保留清单顺序。工具不发现遗漏文件，也不检测所有密钥，需人工审查列表和正文。

`inventory` 记录相对路径、SHA-256、字节数、物理行数与非空行数。原生／二进制文件可登记哈希，不能作为程序正文导出。`extract` 写入前复核哈希，仅去掉全空白行，保留其他原始字符及注释，输出：

| 文件 | 用途 |
|---|---|
| `selected-source.txt` | 选中的原始非空源码行，不增加文件标签或填充内容 |
| `pages.json` | 逻辑页与行对应的相对文件、原始物理行号、全局非空行号 |
| `source-manifest.json` | 本次清单、编码与哈希副本 |
| `review.json` | 行数、选取方式、名称／版本和待审状态 |

默认每逻辑页50行、前后各30页。不超过3000非空行时全量输出；超过时取前1500与后1500行，不重叠。已确认的不同要求可用 `--lines-per-page`、`--side-pages` 配置。这是排版选择，不是对法定源码行的定义。短完整程序最后一页保持真实行数，不填充。完整短程序和局部脚本提取量较少是两种情况。

工具始终报告 `scope_status: unreviewed`；哈希成功仅证明列入文件与清单一致。完整范围、权属和排除理由另留人工证据。工具不生成 Word／PDF、不导出专有 HMI 工程、不解析程序语义、不证明权属，也不提交申请。

## 排版与比对

按 `pages.json` 在文档工具中明确分页，加入准确名称／版本页眉。文件标签、页眉与行号属于辅助标记，不算原始源码行。工作归档保留完整程序顺序，提取说明注明省略的中间范围。渲染 PDF 后逐页检查，文字与 `selected-source.txt` 逐行比对，只允许已记录的版面规范化。关注长行折行、制表符、汉字字形、首尾行和程序结束位置。溢出多出几页，不代表源码变多。

缺源码时，继续有依据的采集表／说明书工作，并写清缺哪个版本的源码、导出或安装包及原因。不能编写合理外观的应用代码掩盖证据缺口。开发或修改软件需作为另一项明确请求处理。
