# 信息采集与撰写

## 对照当前模板

先读实际表格，列出每个题目、填写位置、提示和字数限制。模板有30项就核30项，不能拿另一张通用表代替。旧版 `.doc` 可用现有办公软件转换；保留原件，核对转换后的版式，不能将 DOCX 改扩展名冒充 `.doc`。

[空白工作记录](../templates/intake.blank.json)只覆盖常见信息，具体以代理和申报系统字段为准。每个事实记录值、状态和来源。状态使用：`confirmed` 权利人确认、`observed` 证据可见、`documented` 指定文档记载、`proposed` 拟填建议、`pending` 未知。事实状态不等于递交审批状态。

| 类别 | 核对内容 |
|---|---|
| 主体与权属 | 著作权人、主体证明、权属与开发方式的依据 |
| 软件身份 | 全称、简称、版本、类别和本次申请边界 |
| 日期 | 实际开发完成、发表状态、时间地点依据；拟填值明确标注 |
| 环境 | 实际硬件／系统、开发工具、运行环境和编程语言 |
| 源码 | 版本、自有代码范围、真实行数、原生工程和排除项 |
| 功能 | 目的、用户／行业、模块、流程和有依据的特点 |
| 联系与签章 | 获准接收人／联系人、最终确认和签章提供者 |

不能从公司名称推断为独立开发或单独享有全部权利。委托、合作、许可修改、转让等情况可能需要额外依据。列出问题，不代编协议或签名。

## 主要功能说明

代理要求至少500汉字时，写足有关内容并留修改余量；统计汉字，不靠标点、英文标识和数字充数。字数要求注明来源。工具命令相对本 Skill 所在目录，正文文件可在其他位置：

```sh
python3 scripts/check_function_text.py main-functions.txt --min-cjk 500
```

工具只检查长度，不判断事实、质量、权属或是否实现。不为达到字数加入空泛套话。

从有依据的内容展开：使用对象与目的、输入／设置、核心模块、一次正常流程、可观察输出、保存记录、异常恢复及有证据的技术特点。功能分别说明源码可见、仅需求记载或待验证。没有项目依据，不写疗效、任意压力／温度范围、算法、云端服务或安全机制。

## 操作说明书

按当前软件界面编写：前提条件、启动／登录（如有）、主界面、设置、正常运行、状态／结束、记录和常见异常。每步写起始状态、用户操作、界面结果和有依据的恢复方式。只写适用模块，图注、控件、单位和页面名称与应用保持一致。

优先使用获准取得的真实截图。只有历史界面或设计预览时，标明来源与版本限制。生成示意图可以解释概念，不能证明软件已运行，不能作为真实软件截图。

## 软件设计说明书

说明实际架构、模块职责、状态流程、数据结构／存储、接口、校验、异常和持久化。区分界面发令、通信确认与控制器实际反馈。不挪用其他产品的生产协议、维护密码和参数限值。图形化 HMI 的画面配置、事件脚本与原生导出可结合说明，不能伪装成纯文本应用。

## 一致性核对

所有文件的软件全称／版本、主体、日期与状态、语言／环境、源码量、模块名称、数据项和功能一致。维护一份事实真源。复制另一款软件的表格只能作为排版起点，必须清掉继承的事实。代理可能同时要求操作与设计文档；一般登记规则提到符合要求的文档鉴别材料，不应据此声称两类说明书都统一强制提交。
